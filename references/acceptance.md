# PNG 确认、代码落地与对照验收

## A. 先明确“图”和“页面”各自的含义

给每份输出标注一种状态：`设计预览PNG`、`实际页面截图（环境/数据）`、`已实现未运行`、`隔离测试通过`、`目标环境验证通过`。设计稿不能标为实测，隔离mock不能标为生产通过。

用户只说“先输出PNG”时，不修改网站。用户确认“改吧”时，必须落到实现并检查真实渲染，不用另一张设计图冒充交付。

## B. PNG 预览规则

1. 检查用户图片是否有可读源文件；缺少源图时说明，不臆造看不见的页面。对局部修改保留非目标区域。
2. 界面图优先用HTML/CSS/SVG或确定坐标绘图生成，保证与实现共用可计算尺寸。仅需真实照片/插画时再考虑图像生成，不能靠生成模型猜文字、图标与对齐。
3. 记录视口、DPR、截图区域、字体、测试数据、界面状态。区别CSS像素与PNG像素：CSS输入框40px，DPR2输出可见高度约80px，不能因截图数字翻倍把真实输入框改成80px。
4. 沿用现有图标、导航顺序与颜色。用户指定保留源图色时取样对应区域；不得改成更鲜艳颜色、拉伸字体、复制含旧文字残影的截图。
5. 原型使用安全的示例账号和虚拟资料，不含真实邀请token、密钥或研究隐私。截图如需编辑删除信息，按当前可用图像编辑规则处理，不绕开工具限制。
6. 输出后实际打开图，检查完整文字、清晰度、裁切、按钮/字段对齐、底部留白；记录PNG尺寸。文字能提取或文件存在都不是视觉检查。
7. 至少覆盖用户指定状态。改动涉及另一个关键状态时，补充第二张，例如收起侧栏+菜单打开。不要为了“完整”给小修输出十张无关图。
8. 只在用户要求/正常开发迭代需要时等待预览确认。已经批准后不反复要求相同确认。

## C. 从预览变成实现

落地前记录4类约束：

| 类别 | 例子 | 验证方式 |
| --- | --- | --- |
| 不可变内容 | 文案、模型、数据、权限与动作 | 字段/请求/回归断言 |
| 精确规格 | 输入高40px、账号抽屉宽542px | computed style / bounding rect |
| 关系约束 | 字段和标题左对齐、胶囊靠标题而非居中 | 矩形差值 |
| 流程约束 | 表单失败可重试、关闭保留草稿 | 实际操作/注入失败 |

- 复用真实处理器，避免为美化复制第二套菜单、保存流程和路由。
- 实现组件作用域内的reset，不全站粗暴重置form/button。邀请表单曾被全局`dialog form{padding:24px}`污染；要检查最终计算样式，不是只读局部CSS。
- 检查脚本和样式加载顺序、动态加载入口、资源版本及缓存策略。先确认当前服务实际使用哪个文件，避免改了另一个端口/旧目录。
- 不为静态CSS改动杀掉正在分析的后台任务。不声称一次HTTP200证明当前修改已经被浏览器加载。

## D. 同条件对照

设计图与实测图使用相同：视口、DPR、浏览器缩放、字体加载结果、状态、文案与数据。未加载字体或不同语言长短导致的布局差，不可误判为CSS修复完成。

1. 截取相同区域，不随意拉伸两张图片“看起来一致”。完整页面另检查有无意外横向滚动。
2. 先核对布局关系，再核对数字样式，最后看阴影/细节；交互另外验证。需要像素对照时可用支持的比较工具或并排/叠加查看，不靠记忆目测。
3. 不以全图像素相同作为唯一验收，字体抗锯齿可能不同。对关键尺寸/锚点采用几何断言。
4. 默认建议容差：普通几何关系±1 CSS px；同机计算样式的指定字号/高度应等于目标；用户要求0像素误差时按明确的物理/可见像素条件验证，不能自动放宽。
5. 用户说“实际可见文字中线”时，元素框中线不够：检查字形可见区域。明确基准是字形、边框还是容器，避免“盒子对齐但视觉没齐”。

可复用的浏览器断言示例（按工具允许的方式运行，不绕开浏览器访问限制）：

```js
const field = await page.locator('#invite-name').boundingBox();
const title = await page.locator('#invite-title').boundingBox();
if (Math.abs(field.x - title.x) > 1) throw Error('字段未与标题左对齐');
if (Math.abs(field.height - 40) > 1) throw Error('输入框高度偏离契约');
const menu = await page.locator('#settings-menu').boundingBox();
const trigger = await page.locator('#settings-trigger').boundingBox();
if (menu.y + menu.height > trigger.y - 7) throw Error('设置菜单未位于触发器上方');
```

最后一条仅适用于上方空间足够、约定8px间距的场景；边界翻转测试应有另一组断言。

## E. 验收矩阵：选择本次相关项

| 场景 | 必须看什么 | 不算通过的证据 |
| --- | --- | --- |
| 侧栏收起 | 只一级图标、无文字残片、flyout可到达、选中路径正确 | 只看展开截图 |
| 菜单 | 设置上方锚点、边界翻转、方向键/Esc、动作一次、焦点返回 | CSS里写了fixed/z-index |
| 抽屉 | 入/出期间transform、退出前保留节点、嵌套Esc顺序、关闭晚到请求 | 只截完全打开状态 |
| 页签 | 前后方向、快速反转、离页取消、输入/轮询不触发、草稿留存 | 等300ms后页面能看见 |
| 邀请表单 | 真实尺寸、统一左对齐、格式与后端一致、错误重试、提交锁定 | PNG中按钮漂亮 |
| 用量图 | self/all权限、模型、7/30天、零值/缺失/失败、历史覆盖 | 模拟图有曲线 |
| 登录 | 匿名壳、不请求私有数据、失败/兑换/成功路径、窄屏 | CSS blur隐藏真实内容 |
| 首屏更新 | 慢JS/冷缓存/热缓存/刷新、没有旧布局闪现与重复控件 | 开发服务器显示200 |

每条记录：通过/失败/未测试/N/A，以及环境和证据。优先修复当前修改引入的失败，不宣称所有历史问题已经清理。

## F. 首屏、缓存与性能

- 首屏初始HTML/CSS即遵循最终骨架；不要先显示旧导航，再让脚本搬运成新布局。
- 延迟脚本加载检查首屏与加载后的导航/标题几何；同类控件数量应仍为1。
- 文件改了页面不变时，依次确认运行地址/目录、HTML资源引用、返回内容/资源版本、缓存和Service Worker（若存在），不先断言“都是浏览器缓存”。
- 轮询和MutationObserver不应不断重建控件/触发动画；ResizeObserver只在必要尺寸变化时重画。
- 性能结论写清环境、数据量、请求类型与并发、是否调用AI、是否模拟带宽。读取列表很快不能推断真实分析快；本机测试不能证明某云套餐够用。

## G. 交付门槛

- PNG任务：实际文件存在、尺寸正确、已打开视觉检查、可预览/下载；未改业务程序。
- 实现任务：已在正确入口加载；已查看真实渲染；通过相关几何及交互断言；没有已知未解释的对照差异。
- 无法运行/登录/测生产时：可以交代码和预览，但明确“实际运行未验证”，指出缺少什么；不得重置用户密码或迁移真实资料来凑测试。
- 输出简短变更列表、测试范围、未测项和相关文件。必要时附前后截图与差异清单。不要把新一轮PNG当作代码完成的替代。
