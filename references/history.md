# 历史依据与适用范围

这些规则来自用户与助手持续修改访谈研究工作台的对话，以及2026-11-06只读核对的实现。它们不是对所有页面的全面审计。

## 用户要求 → 可复用决策

| 历史问题/要求 | 本技能规则 | 证据级别 |
| --- | --- | --- |
| “堆了一大堆功能，不知道到底要做什么” | 先确定一个端到端研究任务，再定位辅助工具 | H |
| 账号管理像独立网站、与分析割裂 | 账号与额度在工作台内以右抽屉呈现 | H |
| 管理员和一般用户页面层级不应相同 | 按角色组织入口，后端权限另行校验 | H + R |
| 侧栏收起出现“访/项”等残字，二级图标乱 | 只保留一级图标，悬浮菜单承载二级目的地 | H |
| “设置菜单一样”“收紧”“近七天也收紧” | 短操作共用密度；时间控件不抢主标题 | H，具体px为I |
| 图表左右挤在抽屉中 | API与Token上下两行，筛选条件归同一数据区 | H |
| owner无上限，但也需要进度条 | 空轨道+无限说明，普通成员真实进度 | H |
| 邀请表单默认灰按钮、大空白；预览与实页不同 | 轻返回、对齐与40px字段；核对全局form内边距 | H，参数为I |

| “你又没有云服务器，怎么实测” | 严格区分本机、模拟、目标环境与推断 | H |
| 代码限制8账号被误认为容量上限 | 账号上限、并发闸门、硬件容量分开讨论 | 历史事实，不作未来默认 |
| PNG多次出现未对齐、颜色擅改 | 可计算排版、原色保真、导出像素/几何检查 | H |

## 案例仓库实现定位线索（相对仓库根目录，使用前复查）

- web/account-drawer.css、account-drawer.js：账号、表单、用量和角色入口。
- short-menus.css、short-menus.js：短操作菜单规格与边缘/键盘处理。
- sidebar-rail.css、sidebar-rail.js、sidebar.js：收起状态、flyout、设置锚点。
- drawer-motion.js、drawer-motion.css、workspace-motion.js：抽屉生命周期和同页页签切换。
- account-center.html：匿名模糊壳上的登录。
- workspace-header.js、research-navigation.js：导航与工具区映射，不凭截图另写路由。
- tests/test_tab_motion_browser.cjs、test_short_menus_browser.cjs、test_home_first_paint.cjs、test_evidence_drawer_browser.cjs、test_login_overlay_browser.cjs：当时的隔离回归测试线索。存在不等于本次已经运行。
- 预览HTML与截图曾放在项目工作区output/design-src与output中。不要把这些路径当成新项目必须采用的目录。

本技能不固定真实账号、端口、密码、API密钥、业务额度、邀请有效期或8账号限制。历史端口曾混淆，继续工作必须确认用户当前使用的服务。引用旧运行笔记而没有现场验证时，标为历史信息。

## 不照搬的内容

- 海报里的蓝色、2020×778尺寸、柱图固定坐标属于该海报，不是网站通用token。
- 542px账号抽屉不等于所有原文、设置和复杂编辑面板都必须542px。
- 36px紧凑控件不等于触摸命中区可以忽视。
- “复用组件”不要求先引入某个框架、组件库或重写网站。
- 历史使用原生确认框不等于已统一成自定义确认框；改交互应保留确认语义并实测，不能只根据计划声称完成。
- 该skill的通过条件是未来执行标准，不是对旧网站全面合格的证明。
