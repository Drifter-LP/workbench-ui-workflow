# 案例实录：访谈分析工作台的组件

以下仅描述该案例。H=用户确认的方向；I=核对的实现参数；R=后续建议。尺寸为 CSS px，不是导出 PNG 的物理像素。不要从本表自动生成其他网站的设计变量。

## 1. 全局视觉与层级

H：简洁、紧凑；辅助操作不争夺视觉重心；避免为了填空白不断增加卡片、图标和说明。文字、数字和图表先准确，再美化。

I：工作台账号区使用以下颜色，可作为同风格模块的起点：

| 角色 | 值 | 用法 |
| --- | --- | --- |
| 主文字 | #173b40 | 标题、账号、主要数值 |
| 辅助文字 | #60797e | 标签、单位、非关键说明 |
| 强调/选中 | #008b81 | 主按钮、激活页签、选中胶囊 |
| 分隔线 | #dbe6e5 | 分组，不靠大空白隔开 |
| 柔和底色 | #f0f7f4 | 今日用量区 |
| 进度轨道 | #d2e9e2 | 所有人一致的轨道 |
| 菜单文字/图标 | #294b4e / #11847e | 短操作菜单 |
| 危险操作 | #bd444b | 删除等操作文字和图标 |

H：已有品牌色/上传原图要求保留时，从源图对应区域取样，不自行换成鲜艳蓝色；不用这套青绿色覆盖海报或其他网站。

I：正文与一级侧栏“访谈整理”对齐到 15px；主分组标题约 15px/700；账号抽屉标题 18px/700；辅助说明 12–13px；邀请表单专用标题 19px。不要把所有标题都改成 19px。

R：同类间距采用已有 token；本基线常用 6、8、10、12、14、18、22、24、28px，不为了凑数任意新造值。页内同级标题、标签和字段对齐线相同；关系近的元素间距小于分组间距。

## 2. 导航侧栏与收起按钮

H：展开时保留现有一级/二级层级；收起时侧栏只显示一级图标，不显示残缺文字，不直接堆二级图标。悬浮一级图标，在侧边弹出与“设置”一致的白色菜单承载二级目的地。

I：桌面侧栏展开 238px、收起 66px；当前桌面规则从 851px 起适用。一级图标按钮高 42px；收起控件为侧栏布局图标而不是粗大的文本箭头，SVG 21px，按钮 32×36px；展开时位于品牌区右侧，收起后居中。窄屏不机械套用 66px 侧栏。

规则：

- 一级图标含义、顺序沿用项目原有图标，不凭感觉换新图。访谈整理为折叠文档，研究分析为三竖条的历史约定。
- 隐藏标签不等于删除可访问名称；每个图标有明确 aria-label 或可访问标签。
- H：侧栏本体不显示二级图标。弹出菜单中是否沿用二级图标，以项目已确认菜单为准；不要擅自把“不在侧栏显示”扩展为“所有菜单都禁用图标”。
- 菜单从当前导航条目的真实目的地构建，不维护第二套可能过期的路由清单。
- I：悬浮离开后约 240ms 延迟关闭；图标到菜单之间有可穿越的指针区域，进入菜单立即取消关闭。点击和键盘也能展开。
- 激活状态根据当前子页面标记一级组，不能依赖鼠标停留决定。

## 3. 短操作菜单（设置、更多、账号操作、结果切换）

H：同类菜单共用一套格式，不混用浏览器默认按钮与自绘菜单。编辑表单和大范围搜索面板不强行改成小菜单。

I：统一参数：

| 属性 | 值 |
| --- | --- |
| 外层 | 白底、1px #dce8e5 边框、12px 圆角、6px 内边距 |
| 阴影 | 0 12px 40px #163c3a24, 0 2px 8px #163c3a0a |
| 菜单行 | 最低 36px 高、padding 6px 8px、圆角 9px |
| 行文字 | 15px / 20px，字重 500 |
| 左图标 | 19×19px、描边 1.6、与文字相隔 9px |
| 右箭头 | 16×16px、辅助色 |
| hover/focus | #edf7f4 底，文字 #008b81；键盘焦点可见 |
| 账号菜单 | 144px 宽；通用菜单至少 144px，长文案可增宽 |

定位规则：

- 用户指定锚点时，以整个触发按钮的 bounding rect 定位，不拿图标或文字子节点的矩形代替。
- H：设置菜单优先在设置按钮正上方，左边缘对齐；I：间隔 8px，上方不够则下翻。
- I：其他短菜单触发器与菜单相隔 4px；距视口边缘至少 12px，不够则翻转/夹紧位置。侧栏 flyout 有自己的可穿越桥接区和定位实现，不强制改成同一算法。
- 横向子菜单测试左右边界，切换/滚动/resize 后更新位置或关闭。
- 祖先有 transform/overflow 时，单靠 position:fixed 和大 z-index 可能错位或被裁切；先确认定位上下文，必要时采用受控 portal 或原生 popover 顶层，不无脑增加 z-index。
- 原生 dialog 内菜单需在合适的宿主/顶层中，不能默认 append 到 body 后就能盖过 modal。
- 删除项文字和图标一起标危险色；保留删除确认流程，不因视觉改造顺手执行删除。

键盘和关闭行为见 states.md。

## 4. 账号抽屉与原文抽屉

H：账号与额度从工作台设置入口打开为右侧抽屉，不另开一个风格割裂的管理主页。关闭后继续原研究。原文核查以只读抽屉服务当前任务，不覆盖未保存编辑。

I：账号抽屉 width:min(542px,100vw)，height:100dvh；白底、无四周圆角，左边 1px 分隔，遮罩 rgba(15,41,43,.15)；内边距 18px 22px，≤460px 改为 16px。标题 18px，关闭按钮 32×32px、图标20px。标题下不再放“当前研究保持打开……”这条冗余介绍。

- 顶部为标题/关闭，其后头像与身份，再是“我的账号/成员管理”页签。
- I：头像34px；姓名15px加粗，角色12px。右端32px双向箭头按钮，悬浮/点击展示“切换账号、退出登录”；同第3节短菜单，不把账号名做成不明确的唯一触发器。
- 管理员和普通成员内容按权限区分；后端也校验，隐藏入口不等于鉴权。
- 账号抽屉和原文抽屉共用进出生命周期，不强行共用内容结构或同一宽度。
- R：存在未保存内容时，任何关闭路径走同一脏状态检查；这是验收目标，不能假称历史全部实现。

## 5. 页签、胶囊与时间选择

H：主要页签用来切换页面内容；“本人/全站”是用量范围筛选，不应被设计成整个页面的主导航。

I：账号页签15px、间距28px、底部padding8px；底部1px分隔，选中项文字强调色+700字重、3px下划线。role=tablist/tab/tabpanel，选中状态与面板一致。

H：本人/全站胶囊紧靠“模型用量”标题，不能居中悬空。仅管理员显示全站。I：标题至胶囊间隔14px，浅青底、padding3px，按钮宽60px、字号13px；选中为青底白字；窄屏可缩至46px。整组使用 group + aria-pressed，不能仅靠颜色告知选择。

I：“近7天/近30天”选择器右对齐，94×32px、6px圆角、padding2px 5px；与胶囊高度协调。不要把筛选器扩大为抢眼的大按钮。窄屏允许筛选行换行，不裁切标签。

H：模型选择为 DeepSeek Flash / 千问 Flash；显示名称与后端模型映射必须核对，不能根据标签猜数据来源。

## 6. 用量与统计图

H：账号抽屉的 API 请求次数与 Token 图表上下各占一行，不在窄抽屉里硬塞左右两栏。本人/全站、模型、日期共同决定数据，不可只改按钮外观。

I：图表区单列gap10px；图表卡圆角9px、padding10px 12px；图表标签13px、数值15px加粗、轴字11px、SVG高112px，宽度取实际容器。高度是当前密度基线，换到大屏仪表盘可以调整。

- H：管理员保留浅青进度轨道，但无进度填充，并写“每日额度不限”；普通成员按已用/上限绘制。
- I：轨道6px高，圆角4px；普通成员fill=min(100%, used/limit)，管理员fill=0%，不伪造无限进度条的百分比。
- H：API调用次数用于额度，Token仅统计，不做第二个相互冲突的额度闸门。历史“普通成员80次/日”只是当时产品规则，改UI不自动更改业务额度。
- 显示实际返回的Token；缺失用量不能当作0消耗，应单独说明。未加载显示“—/读取中”，只有成功读取的零值才显示0。
- 历史不完整时标明覆盖范围；空白不自动解释为用户没用过。日期切换要同时检查聚合与横轴。
- 比例图使用明确刻度；若横轴上限50%，46.2%不能画成代表100%的满轨道。虚线等参考标记不能冒充另一个数据系列。
- 标题/数值/单位、空值、长标签、全零、单峰大值均须实测，不能只看有数据的漂亮示意图。

## 7. 表单：邀请成员的具体基线

H：不用原生灰色大返回按钮；不再套卡片；返回入口轻量化；标题、标签、输入框、主按钮、规则区统一左对齐。用文字解释邀请，不用额外图标填空白。

I：

| 元素 | 规格 |
| --- | --- |
| 返回 | 13px辅助色、24px高、15px左尖括号图标、gap5px、无背景边框 |
| “邀请成员”标题 | 19px/700、行高1.4、上13px下5px |
| 一句话介绍 | 13px辅助色 |
| 表单 | 上22px，padding:0，避免继承 dialog form 的24px内边距 |
| 标签 | 14px/600，标签与输入相隔8px |
| 输入框 | 40px高、宽100%、padding0 12px、6px圆角、1px #cddedb边框、字13px |
| 格式帮助 | 12px辅助色、上7px下18px |
| 主按钮 | 36px高、padding0 14px、14px/500、6px圆角；链条图标16px、gap7px |
| 规则区 | 上24px、1px分隔线、内上14px、12px/1.9 |

文案位置：介绍说明“创建账号并生成专属链接”；字段下说明格式；底部说明“私下发送、有效期、一次性、对方设置密码、资料库/额度”。准确规则读取服务端，不能把旧截图里的天数、次数和账号字符集合当成永久约定。历史曾漏写允许点号，实际实现又要求首字符字母或数字，因此前后端需一起核对。

状态：字段有真实label，帮助文字通过aria-describedby关联；无效输入不发送请求；提交中禁用重复操作；失败保留输入并恢复按钮；成功显示安全可复制的链接/状态；不在日志和示例图暴露真实邀请令牌。

## 8. 登录面板

H：登录像浮在工作台上方；背景保持整体品牌和布局联系，模糊、不可操作；不要求先登录才能看到真实研究资料的模糊影子。

I：背景blur4px；面板width:min(420px,100%)、padding30px 34px 32px、圆角14px、轻边框和阴影；标题20px、输入和主按钮40px高；窄屏外侧16px、卡内26px 24px。

安全规则：背景是匿名静态壳或占位数据，不得先读取真实访谈再用CSS模糊。背景inert/aria-hidden，登录表单清晰可聚焦。登录/兑换成功进入主工作区，不再停留在独立账号门户。测试错误密码、网络失败、无效/过期邀请、已登录、窄屏与键盘流程。模糊是视觉效果，不是访问控制。
